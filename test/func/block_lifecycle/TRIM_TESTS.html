空闲块缩减测试点与用例

本页目录

先确定契约：recycle_using_qu_without_lock 末尾调用 adjust_free_block；空闲数严格大于 max_free_block_count 才调整，保留数取 ini_free_block_count 与饱和的 min_count - in_use_count 的较大值。min_count 同时是初始化数量及总块数下限，max_count 是总块数上限。默认 UINT32_MAX 禁用调整，ini 不得大于 max。保留从 head_ 起的热前缀并断开冷后缀，不用 pop 释放热块。计数、恢复和调整共享分配锁；仅释放缓冲区和位图，描述符保护旧切片校验。

测试点 / CTest 后缀 用例与预期
default 默认及显式 UINT32_MAX 不缩减；原有块上限不变
limits ini > max 构造失败；未指定有限 max 对应的 ini 时失败；0/0、相等阈值和大于池容量的阈值均合法
single、1n、nn 三种块策略逐一覆盖空闲数等于/超过阈值、目标为 0、目标等于阈值及重复突发；核对数量、64 字节对齐、恢复后的字节与位图
held 保留有效切片及未读尾部，其他块触发缩减；持有的数据保持逐字节正确，仅真正 Free 的块可释放
preallocate 缩减后重新预分配至 max_count，预分配不改变 min_count 下限；没有新归还块的扫描也会调整，多轮恢复不增加描述符数量
restore_failure 在恢复描述符时注入分配失败；块数不虚增、描述符放回，下次 get/preallocate 正常恢复
force_ignore 强制回收后释放缓冲区和位图；旧切片在 Free 及新代下分别释放，非严格模式安全忽略，不改变新代计数和数据
get_apis 三种取块入口直接取空闲块不调整，缺块时在回收扫描末尾调整；显式扫描按总块数下限调整
concurrent 四个取块线程、四个消费释放线程传递独立序号及反码，反复恢复/缩减；总块数在 min_count 与 max_count 之间，无缺失、重复、覆盖和悬空访问
slice_pool 三种 SlicePool 构造参数透传，突发分配后释放并再次换块，实际块数下降且新切片可用
death_free、death_stale 严格模式下，已缩减 Free 块的旧切片、已恢复新代块的旧切片分别报告准确错误，不能因位图被释放而崩溃
hot_prefix 八块按已知顺序归还后保留栈顶两块；核对后续取出地址、顺序及原有数据，较旧六块缓冲区和位图均释放
initial_floor 组合 initial=0/3/8、在用=0/2/5/8、阈值=0/2/8 及目标=0/阈值；验证精确保留量、等于阈值不调整、不发生减法下溢、重复扫描不突破下限
stack_suffix 单向栈保留 0 到超出长度个节点、空栈；核对被断开链及保留前缀的所有地址和顺序

测试通过友元检查实际拥有的缓冲区和位图、空闲链节点数量、统计值、使用队列及描述符槽位的一致性；遍历仅用于测试断言，不出现在生产计数路径中。Windows 全量回归，Linux TSan 与 ASan/UBSan 运行缩减及原有块生命周期用例。
