1. Start with the smallest example

01_basic.cpp creates a Writer and TwoBufQueue, writes messages, receives callbacks, then calls writer.finish() and queue.stop(). Writer runs in the application's producer thread; the default asynchronous queue reads and invokes callbacks in background workers. Then choose a topic below.

2. Use the complete TwoBufQueue

Example Read it when What it demonstrates
02_batch_callback.cpp One callback should receive grouped data TwoBufQueueBatch passes a DataBatch; the example splits each frame into records itself.
03_multi_thread_writer.cpp Multiple producer threads write One Writer per thread, distinct thread_id values, and multiple layer-1 copy threads.
04_layer1_callback.cpp Process source blocks directly Implement ReadWriterDataCallback and give it to ReadWorker; read completed/current blocks without output copying.
05_seq_writer.cpp Records need sequence numbers Independent SeqWriters share an atomic counter; fetch_add assigns sequence numbers and each Writer's order is verified.
06_sync_writer.cpp Call back in the producer thread Use the same callback shape as 01 and add SyncContext<decltype(rcvCallback)> to Writer; the callback completes before write returns.
07_quick_write_muti_msg.cpp Write many records consecutively Single-block Session, nested write/acquisition loops, and explicit optional flush.
08_all_parameters.cpp Tune a working configuration Every Writer template argument, source pool/backpressure setting, reader setting and TwoBufQueue constructor option.
09_async_logger.cpp Send application logs to background file I/O Independent copying/callbacks, bounded pools, Block/Drop pressure, flush, draining shutdown and complete file verification.

Suggested route: 01 → 02 for individual-record and grouped callbacks. Read 03 for concurrency or 04 for direct source access. 05 and 08 cover sequence numbers and configuration. Use 07 for repeated fast writes, 06 for producer-thread callbacks, and 09 for file logging. The logging guide explains queue flush versus file flush.

3. Use individual components

Example Read it when What it demonstrates
11_warm_pool.cpp Reuse pooled resources Implement reset(), borrow a Loan and return it with finish().
12_warm_pool_factory.cpp Customize creation/destruction Supply Factory::create() and dispose() in addition to the basic pool protocol.
13_spsc_live_handoff_queue.cpp Read a resource while production continues Pool-backed SPSC handoff with current-resource access; try_pop removes records and the consumer retains pending work.
14_spsc_live_handoff_queue_claim.cpp Keep pending records in the queue Use try_claim/cancel_claim instead of pop to preserve an unhandled head record.
15_handoff_queue.cpp Let the queue run a consumer SPSC HandoffQueue's built-in Reader invokes bool(Message&); false requests a later retry.
16_handoff_queue_mpmc.cpp Multiple producers and consumers share work MPMC mode with several producer threads and built-in Readers executing callbacks concurrently.

Start with 11, then 12 for custom lifetimes. Choose 13 → 14 for resources that are still being produced. Choose 15 → 16 when processing begins after send(). Examples 13/14 manage their consumer thread; HandoffQueue manages Readers in 15/16.

4. Build, run and understand callbacks

From the repository root:

Shell
cmake -S . -B build -DBRQ_BUILD_TESTS=OFF -DBRQ_BUILD_EXAMPLES=ON -DBRQ_BUILD_BENCHMARKS=OFF
cmake --build build --config Release --parallel
ctest --test-dir build -C Release -R '^example_' --output-on-failure

Build one target with, for example, cmake --build build --config Release --target brq_component_15_handoff_queue. On Windows with Ninja/MinGW, run build/brq_component_15_handoff_queue.exe; Visual Studio places it under build/Release/. Examples are independent programs: zero exit status means success.

Respect three boundaries: never access a resource after finish/return; borrowed DataBatch, source-block and payload pointers cannot outlive their callback; end producers before draining/stopping consumers. A false callback result means different things in different interfaces, as described in each example.

example_support.hpp contains shared example checks/parsing and includes TwoBufQueue.hpp; applications do not need this helper. Continue with the WarmPool, SpscLiveHandoffQueue and HandoffQueue headers for their complete interfaces.
