## 按消息长度查看吞吐

条形长度仅在同一消息长度内比较。单位 M条/s = 每秒百万条消息。

90 次正式测量 15 次负载校验 消息计数 / FIFO 校验通过 写入失败为 0 p999 样本量提示

TwoBufQueue 的第一层与第二层各 8 MiB，合计 16 MiB；三种开源 SPSC 请求 8 MiB。ReaderWriterQueue 会按内部块容量略微取整。

每条消息的模拟业务循环为 0；仍保留逐消息回调、序号/条数校验和队列自身的消费工作。

本页仅比较16 B与32 B。TwoBufQueue完整遍历每种长度135组参数，回调循环0，所有阶段每次一千万条、预热五万条、5次平均。最终候选把两种长度随机交错复测，未剔除异常值。

每层消息数据区固定8 MiB：block_size × pool_min = block_size × pool_max = 8 MiB；至少2块，未使用单个8 MiB块。8 MiB是消息数据区预算，队列元数据和计时前准备的输入不计入这个数据区，也不等于进程RSS。

扫描当前块关闭、publish_count=UINT32_MAX、两层复制和独立回调线程保留。遍历和正式复测使用同一二进制、缓存与分轮条件；吞吐与各分位数分别选优。

ReaderWriterQueue默认构造略向上取整，因此另外完整遍历9种接收策略，并下调请求条数，使全部512槽位块的数据区合计8 MiB。保留槽位导致可用消息容量约7.984 MiB；其余对照可用数据容量8 MiB。没有修改第三方实现或负载复制代码。

原始完整参数、全部候选、失败日志、校验与对照数据均保存；本次没有失败运行。p999仅按有限样本观察，不承诺长期最低。

## 测试口径与复现信息

在声明的参数空间与预算内搜索；吞吐、p50、p99、p999 分别选优，并各做独立正式复测。表中不同指标可能来自不同配置，完整参数按指标列出。

### 发送、复制与排空

TwoBufQueue：Writer → 复制线程 → 第二层缓存 → 独立回调线程，逐消息调用回调。

源块 / 输出块按指标分别选择；每层数据字节预算保持不变。四种实现正式写入次数与净负载长度相同。

每轮上限按缓存的 80% / 消息字节数计算。TwoBufQueue 不扫描当前块，publish_count 为 UINT32_MAX；停止发送计时后调用 finish_block 交接当前块，再等待本轮全部回调完成。预热也在计时外交接，最终尾部统一 finish。没有增加额外消息，原生 SPSC 每条已发布，轮末无需额外交接。

两份报告同时改变缓存大小与回调工作量，不能将两组差异全部归因于缓存；比较容量影响需另做相同回调负载的对照。

不逐条 flush · 轮末计时外交接；publish_count 按指标分别选择。仅预触碰写端数据页，第二层数据页没有额外预触碰。

吞吐和分组延时均在计时前准备整轮输入；每条消息的全部字都随序号变化；复制构造函数体使用一次直接 memcpy，目标成员保留 bytes{} 初始化。输入缓冲单独计算，不算队列容量，也不保证常驻 L1。

### 时钟、调度与限制

本机为 macOS-14.4.1-arm64-arm-64bit / arm64，Release 优化构建。

计时器：mach_absolute_time；每组 1000 次写入。组均值刻度约 0.0417 ns / 次。

写线程调度：高 QoS · 未硬绑核。调度打断和其他系统活动仍可能影响结果；复制与回调线程保留自身调度策略。

吞吐只累计写线程发送时间；排空在计时之外。并发复制 / 回调仍可能争用缓存和带宽，因此不是持续端到端吞吐。

**p999 仅供观察：** 每次延时测量约有 9,966–9,990 个组均值样本，少于框架建议的 100,000 个。p999 的尾部覆盖有限，不能据此做稳定的尾延时承诺。p999 表示 99.9% 分位数；平均值不代表置信区间。
