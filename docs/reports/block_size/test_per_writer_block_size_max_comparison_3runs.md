# MAX 发布：单线程与完整流水线对照

32 B 普通 write 发布次数 UINT32_MAX 关闭 current 扫描 3 次独立运行取平均

修正每轮上限：按 reader 实际总容量的 80% 计算。每项正式发送 1,000 万条（320,000,000 B，约 305 MiB），预热 5 万条；本轮各配置均一次连续写完，然后等待完成。

writer 池上限 2 GiB；reader 基础上限 2 GiB，单块始终为 writer 的 10 倍，不足一个块时按已有配置提升上限。初始各 2 块（受上限约束），之后按需增长。数据准备不计时，整个 32 B 负载随消息序号变化。高 QoS，接电源，未硬绑核。

完整流水线保留复制线程和回调线程；回调业务循环次数为 0。单线程仅使用 Writer、pool 和交接队列，在同线程立即归还完成块。两者沿用相同分轮上限，单线程只引用 reader 容量计算，不创建 reader 池。

吞吐累计发送区间；区间内的正常申请、换块、通知和归还成本计时，轮末 finish/交接与排空不计时。吞吐与延时分别运行；p50/p99/p999 是每组 1,000 次写入平均耗时的分位数，再对 3 次运行取平均。数据校验独立运行。保留全部 3 次结果，不筛选最快值。
